Three pieces, all from the package's main entry:

| Piece             | What it does                                                                 |
| ----------------- | ---------------------------------------------------------------------------- |
| `PreviewProvider` | Holds the config, reads the downloads and the bucket's list, and confirms each start |
| `PreviewList`     | The ready-made screen for QA                                                 |
| `usePreview()`    | The same list and actions, for a screen of your own                          |

## The provider

Put it near the root of the app, around everything:

```tsx
import { PreviewProvider } from '@axonpack/preview';
import { previewConfig } from './preview-config';

export default function Root() {
  return (
    <PreviewProvider config={previewConfig}>
      <App />
    </PreviewProvider>
  );
}
```

The config is on [Settings and env files](/docs/preview/environment#the-apps-settings), and every
field is on [Reference](/docs/preview/reference#previewconfig).

<Callout type="warn" title="Mount it on every start">
Once the provider has mounted, it tells the native side that this start worked. The crash fallback
waits for that: a preview that never gets that far is marked broken, and the next start loads the
default bundle. So mount the provider on every start, also in builds where `enabled` is false, and not
behind a login or a lazy screen.
</Callout>

## enabled

`enabled: true` turns previews on. The package does no build-type or store detection: you decide per
build. With `false` the provider never reads the downloads or asks the bucket. The list does not hide
itself, so leave it out of builds where previews are off; `usePreview().enabled` tells you which.

A common setup is an internal build with previews on and a store build with them off, from one env
value:

```ts
enabled: process.env.EXPO_PUBLIC_PREVIEWS === 'on',
```

It applies to debug builds too. A preview chosen in a debug build loads instead of Metro, and the
list says Metro is bypassed. **Use the default bundle** returns to Metro.

## The ready-made list

```tsx
import { PreviewList } from '@axonpack/preview';

export default function PreviewsScreen() {
  return <PreviewList style={{ flex: 1 }} />;
}
```

Put it on a screen QA can reach: a tab in internal builds, a settings row, or a hidden gesture. See
[Show the list anywhere](#show-the-list-anywhere). It shows:

- **Running:** what this start runs (the default bundle or a preview), and **Use the default bundle**.
- **The previews for this build**, each with its title, branch, state, environment, who published
  it and when, size and changelog, one action (**Download**, **Switch** or **Update**) and
  **Delete**. The one that runs says Active.
- **Incompatible:** downloads made for another native build, with **Delete all**.
- **Dev preview servers**, in a debug build with that option on. See
  [Dev preview servers](/docs/preview/dev-preview-servers).

| State            | Meaning                                                                  |
| ---------------- | ------------------------------------------------------------------------ |
| Not downloaded   | Published for this build, not on the device                              |
| Downloading      | With a progress bar                                                      |
| Downloaded       | On the device and up to date                                             |
| Update available | Published again since it was downloaded                                  |
| Unpublished      | Still on the device, but no longer in the bucket                         |
| Broken           | It stopped while starting, so the default bundle loaded                  |

**Download** puts a preview on the device and **Switch** restarts into it. Deleting the preview that
runs goes back to the default bundle first.

### Theme and labels

The list follows the device's light or dark mode. Change any colour, the radius or the fonts, and any
text:

```tsx
<PreviewList
  theme={{ mode: 'dark', primary: '#16a34a', radius: 8, fonts: { bold: 'Inter-Bold' } }}
  labels={{ title: 'QA builds', backToDefault: 'Back to the store build' }}
/>
```

`backToBase` still works but is deprecated. It is used only when `backToDefault` is not set.

Every token and label is on [Reference](/docs/preview/reference#theme). `LIGHT_THEME`, `DARK_THEME`
and `DEFAULT_LABELS` are exported to build on.

### Layout and your own content

`PreviewList` is a FlatList, so it takes FlatList's props too. By default the end of the list leaves
room for a floating tab bar; set your own with `contentContainerStyle`. Add your own content above
the header card with `ListHeaderComponent`, or after the last row with `ListFooterComponent`:

```tsx
<PreviewList
  style={{ flex: 1 }}
  contentContainerStyle={{ paddingBottom: 140 }}
  ListFooterComponent={<Text style={{ textAlign: 'center' }}>Build 1.4.0 (212)</Text>}
/>
```

Every prop, and the few the list keeps for itself, are on
[Reference](/docs/preview/reference#previewlist-props).

## Show the list anywhere

`PreviewList` is an ordinary React Native component. It brings no navigation and no screen of its
own, so put it wherever QA can reach it: its own screen, a tab, a stack screen, a `Modal`, a bottom
sheet, a hidden debug screen, or behind a shake or a long press.

What it needs:

- **The provider above it.** Without one it throws `usePreview needs a <PreviewProvider> above it.`
  A provider at the root covers every screen and modal. If a bottom sheet or portal library renders
  its content somewhere else in the tree, that place has to be inside the provider too.
- **A bounded height.** It is a FlatList, so give it `style={{ flex: 1 }}` inside a parent that has
  a height: a screen, or a view with `flex: 1`. Never put it inside a vertical `ScrollView`. Nested
  lists warn and stop virtualizing. Add your own content with `ListHeaderComponent` and
  `ListFooterComponent` instead.
- **Your own way to open and close it.** There is no ready-made modal, and `usePreview()` has no show
  or hide. The screen, tab or modal that holds the list decides when it shows.

It can be mounted in more than one place at once, and mounted and unmounted as often as you like.
Its state lives in module stores, so every copy shows the same list. Opening it does not ask the
bucket again: the provider did that at start, and a pull down or **Refresh** asks again. Dev preview
servers are looked for only while a list is mounted, and the search stops when the last one
unmounts.

The list does not hide itself when `enabled` is false, so hiding the tab, button or gesture that
opens it in store builds is the app's job. `usePreview().enabled` tells you when.

### A screen with expo-router

```tsx
// app/previews.tsx
import { PreviewList } from '@axonpack/preview';

export default function PreviewsScreen() {
  return <PreviewList style={{ flex: 1 }} />;
}
```

Open it from a settings row or a debug menu with `router.push('/previews')`.

### A modal

The app keeps the open state. The close button is the list's own `ListHeaderComponent`, above the
header card:

```tsx
import { PreviewList, usePreview } from '@axonpack/preview';
import { useState } from 'react';
import { Button, Modal } from 'react-native';
import { SafeAreaView } from 'react-native-safe-area-context';

export function PreviewsButton() {
  const { enabled } = usePreview();
  const [open, setOpen] = useState(false);
  if (!enabled) return null;
  return (
    <>
      <Button title="Previews" onPress={() => setOpen(true)} />
      <Modal visible={open} animationType="slide" onRequestClose={() => setOpen(false)}>
        <SafeAreaView style={{ flex: 1 }}>
          <PreviewList
            style={{ flex: 1 }}
            ListHeaderComponent={<Button title="Close" onPress={() => setOpen(false)} />}
          />
        </SafeAreaView>
      </Modal>
    </>
  );
}
```

A bottom sheet, a shake or a gesture works the same way: whatever opens it sets `open`.

### A tab with a floating tab bar

By default the end of the list leaves room for iOS 26's floating tab bar. For a tab bar of your own
that floats over the content, set `paddingBottom` to fit it:

```tsx
// app/(tabs)/previews.tsx
import { PreviewList } from '@axonpack/preview';

export default function PreviewsTab() {
  // Your tab bar's height, the space under it, and a gap.
  return <PreviewList style={{ flex: 1 }} contentContainerStyle={{ paddingBottom: 120 }} />;
}
```

## Your own screen

`usePreview()` gives the same data and actions. It needs the provider above it.

```tsx
import { usePreview } from '@axonpack/preview';
import { Button, FlatList, Text, View } from 'react-native';

export function MyPreviews() {
  const preview = usePreview();
  if (!preview.enabled) return null;
  return (
    <FlatList
      data={preview.items}
      refreshing={preview.loading}
      onRefresh={preview.refresh}
      keyExtractor={(item) => item.id}
      renderItem={({ item }) => (
        <View>
          <Text>{item.entry.title} ({item.status})</Text>
          <Button title="Switch" onPress={() => preview.switchTo(item.id)} />
        </View>
      )}
      ListFooterComponent={<Button title="Use the default bundle" onPress={() => preview.switchTo(null)} />}
    />
  );
}
```

The fields and actions are on [Reference](/docs/preview/reference#usepreview).

## A banner that says what runs

So QA always knows what they are looking at, and how to get back. `useRunning()` says what this
start runs: a dev preview server, a preview, or the default bundle.

```tsx
import { useRunning } from '@axonpack/preview';
import { Text, View } from 'react-native';

export function BundleBanner() {
  const running = useRunning();
  if (running.kind === 'default') return null;
  const label =
    running.kind === 'preview'
      ? `Preview: ${running.title}`
      : `Dev server: ${running.server?.title ?? running.hostPort}`;
  return (
    <View style={{ backgroundColor: '#1d4ed8', padding: 8 }}>
      <Text style={{ color: 'white' }}>{label}</Text>
    </View>
  );
}
```

Render it inside the provider, above your navigation. The example app shows one on every tab.

The repository's
