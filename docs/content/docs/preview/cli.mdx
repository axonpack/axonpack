The CLI comes with the package as `preview`. Run it from your app's root with your package manager:
`npx preview`, `bunx preview`, `pnpm exec preview` or `yarn preview`. `preview --help` prints the
same list.

```
preview <command> [options]
```

## publish

Builds this app's JS bundle and uploads it as a preview. See [Publishing](/docs/preview/publishing).

| Option                     | Default                     | What it does                                                                   |
| -------------------------- | --------------------------- | ------------------------------------------------------------------------------ |
| `--id <id>`                | the git branch              | The preview's id. Publishing an id again replaces it                           |
| `--title <title>`          | asked, prefilled from the id | The name QA sees. Without it a terminal asks; Enter keeps the readable id. No prompt without a terminal |
| `--platform <p>`           | `all`                       | `android`, `ios` or `all`                                                      |
| `--base <branch>`          | the repo's default branch   | The branch the changelog counts commits from                                   |
| `--changelog=<text>`       | the commit subjects         | Changelog text. Use `=` when it starts with a dash, as a `- item` list does    |
| `--changelog-file <path>`  |                             | Read the changelog from a file                                                 |
| `--entry-file <path>`      | Expo's own                  | Passed to `expo export:embed`                                                  |
| `--compatibility <c>`      | the plugin option           | `appVersion` or `fingerprint`. Overrides the app config, with a warning        |
| `--environment <name>`     |                             | Build with this EAS environment's variables, like `eas update`, and record its name, which the app shows as `env: <name>`. Needs eas-cli and a project linked to EAS; shell variables win. See [Settings and env files](/docs/preview/environment#building-with-an-eas-environment) |

For each platform it prints these lines, with the output of `expo export:embed` after the first:

```
android: building task-1
android: uploading 31/79 (1.2/23.4 MB) drawable-xxhdpi/foo.png
android: 79 files, 12 new, 67 already in the bucket
android: published task-1 for build version-1.0.0
android: https://<server>/<bucket>/<slug>/index/android/version-1.0.0.json
```

The `uploading` line gives the file it is on, its number out of all the files, and how many MB of
the files before it are done. In a terminal it is one line, redrawn for each file and cleared once
every file is up. Without a terminal, as in CI, it is printed for the 1st file, the 21st, the 41st
and so on.
A file the bucket already has under its sha256 is not sent again. The next line counts the files
that were new and the ones that were already in the bucket.

The last two lines name the build key and the URL of that build's index in the bucket. `<key>` is
the build's compatibility key, so it has to match the key in the installed build for the preview to
show in its list.

## unpublish

```sh
preview unpublish <id>
```

Removes a preview from every build's list and deletes its manifests. Its files stay until `prune`.
A copy already on a device stays there, shown as Unpublished.

## prune

```sh
preview prune
```

Deletes every file in the bucket that no preview uses any more.

## start

```sh
preview start [--title <title>] [--ports <from>-<to>] [-- <expo start args>]
```

Runs Metro on a free port and announces it to the app's Dev preview servers, once Metro answers and
on the port it really took. Phones on the same network find it with no address typed in, by
sweeping their own network. See [Dev preview servers](/docs/preview/dev-preview-servers).

Once Metro answers, it prints the port, then one line for each private IPv4 address of the
computer, which is what a phone types in **Add a host** when the sweep doesn't reach the computer.
A computer with no such address gets no line:

```
preview: Login fix on port 8082, announced on http://127.0.0.1:19150
preview: On a phone on this Wi-Fi: Add a host → 192.168.1.38
```

| Option                 | Default                         | What it does                                                   |
| ---------------------- | ------------------------------- | -------------------------------------------------------------- |
| `--title <title>`      | asked, prefilled from the branch | The name the app's list shows. Asked like `publish`           |
| `--ports <from>-<to>`  | `8081-8099`                     | The ports to pick from                                         |
| `-- <args>`            |                                 | Everything after `--` goes to `expo start` untouched           |

## Settings

`publish`, `unpublish` and `prune` need the bucket and the write key. They come from the environment
(the shell, or CI secrets). For local use they can also go in the app's `.env.local`, or any env file
Expo loads for a release build; the environment wins over them. Keep the write key out of a committed
`.env`.

| Variable                       | Needed | What it is                                                                 |
| ------------------------------ | ------ | -------------------------------------------------------------------------- |
| `PREVIEW_S3_URL`               | Yes    | `<endpoint>/<bucket>`, for example `http://localhost:9000/previews-public`. Each app's previews go in a folder named after its slug |
| `PREVIEW_S3_ACCESS_KEY_ID`     | Yes    | The write key                                                              |
| `PREVIEW_S3_SECRET_ACCESS_KEY` | Yes    | Its secret                                                                 |
| `PREVIEW_S3_REGION`            | No     | Default `us-east-1`                                                        |

`start` needs none of them.

## Errors and retries

When a request to the bucket can't be sent, or the connection drops before the answer, the message
names the request and the reason Node gave, with its error code:

```
preview: PUT files/<sha256> failed: ECONNRESET read ECONNRESET
preview: HEAD files/<sha256> failed: ENOTFOUND getaddrinfo ENOTFOUND minio.example.com
```

Keys are shown as they are inside the app's slug folder. A listing, from `prune`, shows its prefix
with the slug instead, such as `GET <slug>/files/ failed: ...`.

When the code says the connection was reset or refused, or timed out (`ECONNRESET`,
`ECONNREFUSED`, `ETIMEDOUT`, `EPIPE`, `UND_ERR_SOCKET` or `UND_ERR_CONNECT_TIMEOUT`), the CLI sends
the request again after 1, 2 and 4 seconds. If the fourth try fails too, the message says so:

```
preview: PUT files/<sha256> failed after 4 tries: ECONNREFUSED connect ECONNREFUSED 203.0.113.7:9000
```

Every request it sends is safe to repeat. A list write whose first try did land gets 412 on the
repeat, and the CLI reads the list again and writes it again, as it does when two publishes clash.

When the bucket answers with an error status, nothing is retried and the message gives the status,
the key and the start of the bucket's answer: `S3 403 for <key>: <body>`.

A publish that stopped partway can be run again. The files already in the bucket are skipped.

## Exit codes

A command that fails prints `preview: <message>` and exits with 1.
