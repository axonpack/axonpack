## Components and hooks

| Export                         | What it is                                                                    |
| ------------------------------ | ----------------------------------------------------------------------------- |
| `PreviewProvider`              | `{ config: PreviewConfig, children }`. Mount it near the root, on every start |
| `PreviewList`                  | The ready-made list. Props below                                              |
| `usePreview()`                 | The list and its actions. Needs the provider above it                         |
| `usePreviewStatus(labels?)`    | What runs now and the build it runs in. See [below](#usepreviewstatus). Needs the provider |
| `useRunning()`                 | What this start runs, as a [`Running`](#running). Needs the provider          |
| `usePreviewsState()`           | The raw [store state](#usepreview), without the provider                      |
| `useDevPreviewServersState()`  | `{ servers, activeUrl, alive, error, scanning, hosts }` for dev preview servers. `alive` is every `host:port` that answered the last look, or null before one |

## PreviewList props

`PreviewList` is a FlatList, and takes FlatList's props as well as its own.

| Prop                    | What it is                                                                   |
| ----------------------- | ---------------------------------------------------------------------------- |
| `theme`                 | Nothing, a partial theme or an expo-devtools palette. See [Theme](#theme)    |
| `labels`                | Any text. See [Labels](#labels)                                              |
| `style`                 | The FlatList's style, over the list's background colour                      |
| `contentContainerStyle` | Over the list's padding: 16 all round and 112 at the end, which clears a floating tab bar. Set `paddingBottom` to fit your own |
| `ListHeaderComponent`   | Your own element above the list's header (the error banner and the header card) |
| `ListFooterComponent`   | Your own element after the last row                                          |
| Any other FlatList prop | Passed through, such as `onScroll`, `testID` or `showsVerticalScrollIndicator` |

The list keeps these for itself, so they can't be passed: `data`, `getItem`, `getItemCount`,
`renderItem`, `keyExtractor`, `ItemSeparatorComponent`, `CellRendererComponent`, `getItemLayout`,
`numColumns`, `columnWrapperStyle`, `horizontal`, `refreshing`, `onRefresh`, `refreshControl` (pull
to refresh is built in, coloured from the theme) and `ListEmptyComponent` (the list always has its
section headings, and says itself when nothing is published).

## PreviewConfig

What the app passes to the provider. Nothing here is read from the environment.

| Field               | Needed | What it is                                                                          |
| ------------------- | ------ | ----------------------------------------------------------------------------------- |
| `enabled`           | Yes    | `true` turns previews on. You decide per build; nothing is detected                 |
| `s3Config`          | No     | The bucket and how to read it (`PreviewS3Config`, below). Without it, the list shows previews as not set up |
| `devPreviewServers` | No     | Lists this app's Metro servers in a debug build. `true`, or an object (below). Default off. See [Dev preview servers](/docs/preview/dev-preview-servers) |
| `buildKey`          | No     | This build's key, only when the config plugin is not used to bake it in             |

`s3Config` (`PreviewS3Config`):

| Field                 | Needed | What it is                                                                          |
| --------------------- | ------ | ----------------------------------------------------------------------------------- |
| `url`                 | Yes    | With a read key: `<endpoint>/<bucket>[/<folder>]`, the same as `PREVIEW_S3_URL`. Without one: any address the files are public under, such as that URL, `https://pub-<id>.r2.dev` or a CDN. Left out or empty at runtime, the list shows previews as not set up |
| `readAccessKeyId`     | No     | A read-only key, for a private bucket. Never the write key                          |
| `readSecretAccessKey` | No     | Its secret                                                                          |
| `region`              | No     | Signing region for a private bucket. Default `us-east-1`; `auto` on R2              |
| `headers`             | No     | Extra headers on every read, for a proxy, CDN or tunnel in front of the bucket      |

```ts
s3Config: {
  url: process.env.EXPO_PUBLIC_PREVIEW_S3_URL as string,
  readAccessKeyId: process.env.EXPO_PUBLIC_PREVIEW_S3_READ_ACCESS_KEY_ID,
  readSecretAccessKey: process.env.EXPO_PUBLIC_PREVIEW_S3_READ_SECRET_ACCESS_KEY,
  region: process.env.EXPO_PUBLIC_PREVIEW_S3_REGION,
},
```

`url` is typed as a string, and an env value can be undefined, so pass it with `as string`. Left
out or empty at runtime, the list shows previews as not set up: the app reads nothing from a bucket
and shows no error, and dev preview servers and the header card work as usual. A `url` that is set
but is not a full address, such as `/previews`, is still an error.

0.1.0 took these five fields at the top level of the config. They still work but are deprecated, and
the old top-level `url` follows the same rule.
When `s3Config` is set too, it wins, and the app logs one warning.

`devPreviewServers` as an object (`DevPreviewServersOptions`). `true` is the same as `{}`.

| Field              | Default | What it is                                                                 |
| ------------------ | ------- | -------------------------------------------------------------------------- |
| `enabled`          | `true`  | Turns the section on                                                       |
| `allowCustomHosts` | `true`  | Shows **Add a host**, so QA can add another computer on the device          |
| `hosts`            | none    | Other computers the app asks, such as `"192.168.1.24"` or `"qa-mac.local:19150"`. The port is the registry's, 19150 when left out. An entry that is not a host, is listed twice, or is this computer is skipped with a `console.warn` |

`localhost`, `127.0.0.1`, and `10.0.2.2` on Android are always checked and need no entry.

```ts
devPreviewServers: {
  allowCustomHosts: true,
  hosts: ["192.168.1.24", "qa-mac.local:19150"],
},
```

## usePreview

| Field                  | What it is                                                                 |
| ---------------------- | -------------------------------------------------------------------------- |
| `enabled`              | `config.enabled`                                                           |
| `previewsConfigured`   | A bucket URL is set. False when `s3Config.url` is undefined, empty or blank |
| `devPreviewServers`    | Whether dev preview servers are on                                         |
| `items`                | [`PreviewItem[]`](#previewitem): this build's previews, and downloads it no longer lists |
| `incompatible`         | Downloads made for another native build                                    |
| `loading`              | A refresh is running                                                       |
| `error`                | The last error, as text, or null                                           |
| `buildKey`             | This build's key, or null without the plugin                               |
| `remote`               | What the bucket lists for this build. Null until it has answered once      |
| `local`                | Every download on the device                                               |
| `downloading`          | Download progress by id, from 0 to 1                                       |
| `activeId`             | The preview the next start loads, or null for the default bundle          |
| `runningId`            | The preview that runs now, or null. Not `activeId` when the chosen one did not load |
| `broken`               | Ids of previews that stopped before they finished starting                 |

| Action                   | What it does                                                             |
| ------------------------ | ------------------------------------------------------------------------ |
| `refresh()`              | Reads the downloads, then asks the bucket for this build's list. With no bucket URL it asks nothing |
| `download(id)`           | Downloads a preview, or its update                                       |
| `switchTo(id)`           | Restarts into a preview, downloading it first if needed                  |
| `switchTo(null)`         | Back to the default bundle. Also stops a dev preview server              |
| `remove(id)`             | Deletes a download. If it runs, goes back to the default bundle first    |
| `removeIncompatible()`   | Deletes every download made for another native build                     |

### PreviewItem

| Field      | What it is                                                                       |
| ---------- | -------------------------------------------------------------------------------- |
| `id`       | The preview's id                                                                 |
| `entry`    | The bucket's entry: `title`, `branch`, `commit`, `author`, `publishedAt`, `appVersion`, `buildNumber`, `compatibility`, `fingerprint`, `environment` (only when published with `--environment`), `size`, `changelog`, `revision`, `manifest` |
| `status`   | `available`, `downloading`, `downloaded`, `update-available`, `unpublished` or `broken` |
| `progress` | 0 to 1 while downloading, else null                                              |
| `active`   | It runs now: what native started from, not only what was chosen                  |
| `local`    | The download on the device, or null                                              |

### Running

| `kind`     | Fields                                                             |
| ---------- | ------------------------------------------------------------------ |
| `default`  | `source` (`built-in`, `expo-dev-server` or `dev-preview-server`), `url`, `hostPort`, `server` |
| `preview`  | `id`, `title`                                                      |
| `local`    | `url`, `hostPort`, `server` (null until the list has found it)     |

0.1.0 called the default bundle `kind: 'base'`, with no other fields. It is `kind: 'default'` now.
A picked server that is the Metro the app starts on anyway counts as the default.

## usePreviewStatus

Everything the list's header card shows, for a banner, badge or debug screen of your own. Pass the
list's `labels` to name the kinds the same way. Its type is `PreviewStatusInfo`.

| Field           | What it is                                                                     |
| --------------- | ------------------------------------------------------------------------------ |
| `running`       | What runs now, as `useRunning()` returns it                                     |
| `kind`          | `default`, `preview` or `local` (a server picked in the list)                  |
| `bundleKind`    | Where it comes from: `built-in`, `expo-dev-server`, `dev-preview-server`, `preview`, or `server` for a server no look has found, whose kind is not known. Picks the header card's chip |
| `title`         | The header card's title: the preview's title, a `preview start` server's title, Default for the Metro the app starts on, another server's address, or the kind's name |
| `id`            | The running preview's id, or null                                              |
| `branch`        | The running preview's or server's branch, or null                              |
| `address`       | A server's `host:port`, with loopback shown as localhost, or null              |
| `label`         | One sentence for what runs, such as "Expo server, localhost:8081"              |
| `isDefault`     | The default bundle runs: nothing picked, or what was picked is what the app starts on anyway |
| `online`        | Whether the server the app runs from answers: false once a look for dev preview servers did not find it. Null for a preview or a bundle built into the app, before the first look, and with dev preview servers off |
| `scanning`      | A full scan of every port for dev preview servers runs now: on open, on refresh, and every 30 seconds. The quick look every 2 seconds does not count |
| `hosts`         | Where the app looks for dev preview servers: `{ host, port, source }`, where `source` is `built-in`, `app` (from the config) or `user` (added on the device). Empty until the first look |
| `environment`   | The running preview's EAS environment, or null                                 |
| `author`        | The running preview's author, or null                                          |
| `commit`        | The running preview's full commit, or null                                     |
| `publishedAt`   | The running preview's ISO publish date, or null                                |
| `app`           | `{ name, version, buildNumber, platform }` of this build. Nulls on a native side older than the JS |
| `compatibility` | `{ mode, key }`: `appVersion` or `fingerprint`, and the build key               |
| `previewsConfigured` | A bucket URL is set. False when `s3Config.url` is undefined, empty or blank, and then nothing is read from a bucket |
| `loading`       | The previews list is loading                                                   |
| `error`         | The last error, as text, or null                                               |
| `canGoBack`     | A preview is chosen (even one that could not load) or a server is picked       |

| Action            | What it does                                                               |
| ----------------- | -------------------------------------------------------------------------- |
| `backToDefault()` | Restarts on the default bundle, clearing the chosen preview and the picked server |
| `refresh()`       | Asks the bucket again, and scans every port for dev preview servers when they are on |

`Running`, `DefaultSource`, `BundleKind`, `PreviewStatusInfo`, `PreviewListProps`,
`PreviewListTheme`, `PreviewListThemeInput`, `PreviewListFonts`, `DevtoolsPaletteLike`,
`PreviewListLabels`, `DevPreviewServersState`, `DevPreviewServer`, `DevPreviewServersOptions`,
`DevServerHost` and `HostAddress`.

`previewsStore` and `devPreviewServersStore` are the stores behind the hooks, with `getState()` and
`subscribe()`, for use outside React. `devPreviewServersStore.addHost({ host, port })` and
`removeHost({ host, port })` add and remove a host on the device, as the list does.

## Theme

`PreviewList`'s `theme` takes one of three things:

- **Nothing.** `LIGHT_THEME` or `DARK_THEME`, following the device. Only these two are built in.
- **A partial `PreviewListTheme`.** Any keys below. The rest come from light or dark, picked by
  `mode`.
- **An expo-devtools palette** (`DevtoolsPaletteLike`, the shape of its `Palette`), told apart by its
  `textPrimary` and `accent` keys. `fromDevtoolsPalette` maps it: `surface` to `card`, `sectionTint`
  to `surface` and `tint`, `textPrimary` to `title` and `text`, `textSecondary` to `muted`, `accent`
  to `primary`, `error` and `errorSurface` to `danger` and `dangerSurface`, and `codeKeyword`,
  `jsonNumber` and `jsonString` to `info`, `accent2` and `accent3`. `mode` comes from how dark its
  background is, and `primaryText` is white or black, whichever reads on `accent`.

A chip's text is its tone on a light wash of it; where the tone would be hard to read on the card
or the header card's tint, its text is darkened (or lightened, on a dark theme) just enough. A tone
that is not a hex colour gets an outline instead of a wash.

| Key             | Light     | Dark      | What it colours                                            |
| --------------- | --------- | --------- | ---------------------------------------------------------- |
| `mode`          | `auto`    | `auto`    | `auto` (follows the device), `light` or `dark`             |
| `background`    | `#f4f6fa` | `#12151f` | Behind the list                                            |
| `card`          | `#ffffff` | `#1c2130` | Each card                                                  |
| `surface`       | `#eef1f6` | `#262c3d` | Behind the changelog and the progress track, and a pressed row |
| `tint`          | `#e6eefc` | `#1f2b47` | The header card, and the row the app runs from             |
| `tintBorder`    | `#c9d6ef` | `#3a4560` | The header card's border, which `border` would lose on the tint |
| `border`        | `#e4e8f0` | `#323a4f` | Card, button and divider lines                             |
| `title`         | `#0f172a` | `#f8fafc` | Headings, and the error snackbar's message                 |
| `text`          | `#334155` | `#cbd5e1` | Body text                                                  |
| `muted`         | `#56637a` | `#94a3b8` | Quiet text: hints, who published and when, size, and plain chips |
| `primary`       | `#2563eb` | `#5b8def` | Main buttons, Show details, the Preview chip and Downloading |
| `primaryText`   | `#ffffff` | `#0b1220` | Text on main buttons                                       |
| `danger`        | `#dc2626` | `#f87171` | Delete, the error snackbar's edge, Offline, Unpublished and Broken |
| `dangerSurface` | `#fff6f6` | `#3b1d1d` | Behind the error snackbar                                  |
| `warning`       | `#d97706` | `#fbbf24` | Update available, Made for another native build, and the Metro note |
| `success`       | `#16a34a` | `#4ade80` | Active and Downloaded                                      |

| `radius`        | `14`      | `14`      | Card corner radius. Buttons scale from it                  |
| `fonts`         | `{}`      | `{}`      | `{ regular, medium, bold }` font family names. Each falls back to the system font |

## Labels

`PreviewList`'s `labels` takes any of these. `DEFAULT_LABELS` has the defaults. A name in
braces, such as `{host}`, is filled in. `status`, `statusShort` and `timeAgo` are merged per key, so
`labels={{ statusShort: { broken: 'Crashed' } }}` changes only that one.

## Config plugin

```json
["@axonpack/preview", { "compatibility": "appVersion" }]
```

| Option          | Default      | Values                       |
| --------------- | ------------ | ---------------------------- |
| `compatibility` | `appVersion` | `appVersion` or `fingerprint` |

See [Compatibility](/docs/preview/compatibility) for what it writes into the build.
