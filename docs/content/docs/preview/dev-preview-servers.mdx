title: Dev preview servers
description: Several Metro servers for one app, one per task or worktree, switched live from one debug build.

---

When you or an AI agent work on several tasks at once, each in its own git worktree with its own
Metro, one installed debug build can list every running Metro for the app and switch between them
live. No rebuild per task.

## Turn it on

One switch in the provider's config:

```ts
<PreviewProvider config={{ ...previewConfig, devPreviewServers: true }}>
```

It is off by default, and it only shows in a debug build. A release build ignores it, even if a
server choice is in the saved state. The app also needs the [config plugin](/docs/preview/compatibility),
which bakes in the app's slug.

To list other computers too, or to hide **Add a host**, pass an object instead of `true`:

```ts
devPreviewServers: {
  allowCustomHosts: true, // the default: QA can add a host on the device
  hosts: ["192.168.1.24", "qa-mac.local:19150"], // the team's own machines
},
```

`enabled` is `true` unless the object says otherwise. See [Hosts](#hosts).

## Start a server per worktree

In each worktree:

```sh
npx preview start                    # a free port in 8081-8099, announced to the app
npx preview start -- --clear         # after --, the arguments go to expo start
npx preview start --title "Login fix"
npx preview start --ports 8100-8120
```

With bun scripts, `bun run` eats the first `--`, so it is `bun run start:preview -- -- --clear`.

In a terminal, `start` asks for the name the app shows, prefilled with the branch's readable title;
Enter keeps it. `--title` skips the question, and so does a run with no terminal, such as an AI
agent's shell, which takes the branch title.

A plain `npx expo start --port 8085` is found too, with less detail: no branch. It shows when the
list opens, when you refresh it, or within 30 seconds.

## Switch servers in the app

Open the list. **Dev preview servers** shows each server for this app in one grouped card. A
`preview start` server shows within about two seconds of announcing itself, and a plain
`expo start` server once the next full scan finds it. Each row has the server's title, its address
and its branch, with chips:

- **Active** on the server the app runs from now. Its row takes the header card's tint.
- **`server: Expo`** on a plain `expo start` or `expo run` Metro, and **`server: Preview`** on one
  started with `preview start`.
- **Default server** on the Metro the app starts on with nothing picked. Metro only knows the app's
  name, which every server of the app shares, so this one is called **Default** unless
  `preview start` gave it a title. Any other server without a title goes by its address.
- **Offline** on the server the app runs from, once it stops answering. Its row stays, with the
  title, branch and kind it had when it last answered, even after a reload. A server the app never
  saw answering shows its address and a plain **Server** chip, since its kind is not known.
- **Made for another native build** or **Native build unknown**. See below.

Tap a row to restart the app on that server. The header card then names it, and **Back to default**
goes back. Stop a server with Ctrl+C and it leaves the list on its own, unless the app
runs from it.

On every start of a debug build the order is: the picked dev preview server, then a downloaded
preview, then the default Metro. Switching to a preview in the list stops using the picked server,
and **Back to default** stops both. Picking the Metro the app starts on anyway changes
nothing, so it counts as the default.

## Hosts

At the end of the servers card, a **Hosts** row with a count opens the list of hosts it checks:

- **This computer**: `localhost`, `127.0.0.1`, and `10.0.2.2` on Android. Always there, never in the
  config. The computer the app's own Metro runs on shows too when it is another address, such as a
  phone on Wi-Fi started from `192.168.1.10`.
- **The app's hosts** from `hosts` in the config. Like the ones above, they can't be removed.
- **Hosts added on the device**, each with a ✕ to remove it.

**Add a host** is the last row of the card. It opens a field in its place for an IP address or a
host name, such as `192.168.1.24` or `qa-mac.local`. Add `:port` only when that computer's registry
is not on 19150. A host that is not an address, is already listed, or is this computer gets a plain
message under the field instead. Added hosts are saved on the device in
`Documents/preview/hosts.json` and come back after a restart. An app that sets
`allowCustomHosts: false` shows no **Add a host**, and ignores hosts added before.

### Other computers show preview servers only

Another computer is never scanned. The app asks its registry, `http://<host>:19150/servers`, and
lists only the servers that registry names, for this app's slug. So a teammate's `npx preview start`
shows, and a plain `npx expo start` on their computer never does. Each row's address says which
computer it is on, so two computers running Metro on 8081 are two rows.

On the same network you don't need to add the computer at all: see
[Found on the network](#found-on-the-network). Add a host for a computer Bonjour can't reach, such as
one on another subnet or behind a VPN. It shows within 2 seconds of its registry answering.

## Found on the network

`preview start` also announces its server over Bonjour, as `_axon-preview._tcp`. While the list is
on screen, the app listens for these announcements, so a teammate's `npx preview start` on the same
Wi-Fi shows with no address typed in. It shows within 2 seconds of the app hearing it.

- **Preview servers only.** Only `preview start` announces, so a plain `npx expo start` on another
  computer still never shows.
- **Each row says which computer.** A server found this way shows its computer's name and port, such
  as `qa-mac:8081`. Two computers running Metro on 8081 are two rows.
- **One row per server.** Your own computer's servers are also announced. The registry tells the app
  its computer's id and LAN addresses, so a server found both on `localhost` and over Bonjour is one
  row. A computer you also added as a host shows once, through its registry.
- **Only this app's servers**, by the slug in the announcement.

The app stops looking while it is in the background, and when the list closes.

### iOS asks first

iOS needs two keys in the app's `Info.plist` before it lets the app look. Add them to the app config:

```json
"ios": {
  "infoPlist": {
    "NSLocalNetworkUsageDescription": "Finds preview servers on your network.",
    "NSBonjourServices": ["_axon-preview._tcp"]
  }
}
```

Then rebuild the app. The first time the list opens, iOS asks the user to allow the app to find
devices on the local network, using that text. If they say no, the app finds nothing over Bonjour
until they allow it in **Settings > Privacy & Security > Local Network**. Without
`_axon-preview._tcp` in `NSBonjourServices`, iOS finds nothing and shows no prompt. The simulator
never asks. Android needs nothing in the app config.

### On the computer

The registry announces on every network the computer is on, and answers the questions other
devices send, on UDP port 5353 next to the system's own Bonjour. No setting is needed. On macOS 15
and later, the terminal app you run `preview start` from needs Local Network access (**System
Settings > Privacy & Security > Local Network**). Without it, macOS drops the announcements, and
phones find nothing. To check from the Mac, run `dns-sd -B _axon-preview._tcp` while
`preview start` runs.

## Which servers are listed

Only servers for this app's slug, the one the config plugin baked in. A build made without the plugin
has no slug, and the section says so instead of listing other apps' servers.

A server for the same app but another native key (another app version, or another fingerprint) is
listed and marked "Made for another native build", since you may still want it. A plain
`expo start` server in fingerprint mode shows "Native build unknown", because its manifest carries no
fingerprint.

## How the app finds them

Four sources, merged by computer and port:

- **The registry.** `preview start` runs `expo start` on a free port and announces it to a small
  registry on your computer, on port 19150, with the branch, the worktree and the native key
  `publish` would use. It announces once Metro answers, on the port Metro really took: Expo moves
  to another port when it finds the first one taken. The first `start` starts the registry, and it exits once no server is left.
  A heartbeat every 5 seconds keeps a server listed; it drops out 15 seconds after the last, so a
  killed process goes too. Its `/servers` also gives the computer's id and LAN addresses.
- **A port scan.** The app asks each port from 8081 to 8099 for Metro's `/status`, then reads the
  Expo manifest of each one it finds for the slug, name, version and bundle URL.
- **Other computers' registries.** Each host from the config or added on the device is asked for its
  registry on 19150, or the port given with it. Only the ports it lists are asked on that computer.
- **Bonjour.** Each registry announces its servers on the network, with the title, branch, slug and
  native key. The app asks Metro at the announced address and port, like a registry's servers.

A server found both ways uses the registry's details. A server Bonjour found on a computer the app
already reaches through a registry is left to that registry.

## How often it looks

Only while the list is on screen, and never while the app is in the background. When the app comes
back to the foreground, it looks once straight away. Off the list's screen, `usePreviewStatus()` and
`useRunning()` run one full scan when they mount, if the app runs from Metro and no server is known
yet, so a banner can name a `preview start` server.

- **Every 2 seconds** it asks the registry, the other computers' registries, the servers it has
  already found, the default Metro and the server the app runs from. That is enough for `preview start` servers: one that starts or stops
  shows or goes within one of these looks, because the registry names its port. A found server is
  asked again each time until it stops answering, then it leaves the list. The one the app runs
  from stays, marked Offline.
- **A full scan** of 8081 to 8099 runs when the list opens, when you pull to refresh or tap Refresh,
  and 30 seconds after the last one. A refresh restarts that count. A spinner shows right after the
  heading's title while it runs. A new plain `expo start` server shows after the next full scan, so
  on open, on refresh, or within 30 seconds.

A look never starts while the last one runs, and a refresh during a scan waits for that scan.

A registry that does not answer, here or on another computer, is left out of the 2 second looks.
It is asked again on the next full scan, and once it answers it is back on every 2 seconds. So the
first `preview start` after the list opened shows on refresh, or within 30 seconds. When Bonjour
hears a new server first, the next 2 second look asks this computer's registry too, and the server
shows straight away.

Each closed port is a refused connection, and iOS writes every one to the Xcode console as
`Could not connect to the server`. JS can't turn that off, so the full scan runs only this often:
expect a burst of those lines every 30 seconds. A server that is down but still asked every 2
seconds (the default Metro, or the server the app runs from) adds one line each time.

## Reaching the servers

The app scans the host its own Metro is on, and asks the registries of the other hosts in the
**Hosts** row.

| Device                 | What to do                                                                 |
| ---------------------- | -------------------------------------------------------------------------- |
| iOS simulator          | Nothing                                                                    |
| Android emulator       | Nothing: the app also tries `10.0.2.2`, which reaches the computer        |
| Phone on USB (Android) | `adb reverse` for each port. `preview start` does it when `adb` is on the PATH |
| Phone on Wi-Fi         | Nothing: it was started from the computer's LAN address, so the others are found there too |

Android 17 asks before an app may reach the local network. If that is denied, the app can't reach any
Metro. Allow it in the app's settings, or on the emulator run
`adb shell pm grant <package> android.permission.ACCESS_LOCAL_NETWORK`.

## Limits

- **Debug builds only.** A release build has no Metro to switch to.
- **Bonjour stays on one network.** It does not cross routers, and most VPNs block it. Add a
  computer on another network as a host.
- **This app only.** Servers for another slug are never listed.
- **Plain HTTP on the local network.** An Expo app's iOS build allows plain HTTP to local addresses
  only, so another host must be on the same network as the device, not a server on the internet.
