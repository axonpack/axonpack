---
title: Preview
description: Set up @axonpack/preview from the devtools config, and switch previews and dev servers from a Preview tab.
---

If the app uses [`@axonpack/preview`](/docs/preview), the devtools can set it up. Pass preview's
config as `preview` in the devtools config. The devtools then put preview's provider around the
app, and a **Preview** tab joins the panel and the Axonpack tab in React Native DevTools. The app
mounts no `PreviewProvider` of its own.

## Set it up

1. Install `@axonpack/preview` 0.2.0 or later and add its config plugin to `app.json`. It has native
   code, so make a new build after. Every step, with its checks, is on preview's
   [Installation](/docs/preview/installation).

   ```sh
   npx expo install @axonpack/preview expo-file-system
   ```

   ```json
   {
     "expo": {
       "plugins": [["@axonpack/preview", { "compatibility": "appVersion" }]]
     }
   }
   ```

2. Pass its config as `preview`:

   ```tsx
   <DevtoolsProvider
     config={{
       enabled: process.env.EXPO_PUBLIC_DEVTOOLS === 'on',
       preview: {
         enabled: true,
         s3Config: { url: process.env.EXPO_PUBLIC_PREVIEW_S3_URL as string },
         devPreviewServers: true,
       },
     }}
   >
     <App />
   </DevtoolsProvider>
   ```

   `preview` takes the same object as preview's own `PreviewProvider`. Every field is on preview's
   [Reference](/docs/preview/reference#previewconfig), and where each value comes from is on
   [Settings and env files](/docs/preview/environment#the-apps-settings).

3. If the app already mounts `<PreviewProvider>`, remove it. The devtools mount it now.

Open the panel. The Preview tab is there, and its header card says what runs now.

Preview's hooks, such as `usePreview()` and `usePreviewStatus()`, and a `PreviewList` of your own
work anywhere inside `DevtoolsProvider`, since its provider is above them.

## Keep the devtools on inside a preview

A preview is a release bundle, so `__DEV__` is `false` while one runs. With `enabled: __DEV__`, the
devtools are off inside every preview, and with them the panel and the Preview tab: QA can switch to
a preview but has no way back from inside it. Give `enabled` a value that is also on in the bundles
QA switches between, such as an env value set for internal builds and for `preview publish`:

```ts
enabled: process.env.EXPO_PUBLIC_DEVTOOLS === 'on',
```

Or keep `enabled: __DEV__` and put preview's list on a screen of your own as well. See
[Show the list anywhere](/docs/preview/app-setup#show-the-list-anywhere).

## With the devtools off

Unlike the tabs' settings, `preview` applies with `enabled: false` too. When the package loads, its
provider goes around the app whether the devtools run or not, because preview has to confirm each
start: a preview whose start is never confirmed is marked broken, and the next start
loads the default bundle. Preview's own `enabled` still decides whether previews are on.

With the devtools off there is no panel, so there is no Preview tab either.

## When preview isn't installed

With `preview` set, the devtools enabled and `@axonpack/preview` missing, the app stops at start
with:

```
The devtools config has `preview`, but @axonpack/preview isn't installed. Install it with `npx expo install @axonpack/preview expo-file-system`, add `@axonpack/preview` to the plugins in app.json, and rebuild the app.
```

With `enabled: false` nothing is thrown, so a release build never stops over it, and preview is left
out. `@axonpack/preview` is an optional peer dependency: an app that doesn't set `preview` doesn't
need it installed.

## The Preview tab

The tab shows preview's own list, in the panel's theme, after Redux in the tab bar. It is there only
when `preview` is set and the package loaded. From the top:

- An error snackbar, only when something went wrong.
- The header card: what runs now, **Back to default**, Refresh, and **Show details**.
- Dev preview servers, in a debug build with `devPreviewServers` on.
- Published previews for this build, with Download, Switch, Update and Delete.
- Incompatible downloads, with **Delete all**.

Each part is described on preview's [App setup](/docs/preview/app-setup#the-ready-made-list).
Switching to a preview or a server restarts the app, as it does from preview's own list.

## In React Native DevTools

The Axonpack tab on your computer has a Preview panel with the same list, after Navigation. Set it
up on [React Native DevTools](/docs/expo-devtools/react-native-devtools). Two things differ:

- Every row is drawn at once and there is no pull to refresh. The header card's Refresh asks again.
- The panel reads the list again each time you open it.

## The config plugin

The devtools don't add preview's config plugin for you. It changes native code, so it goes in
`app.json` with the app's other plugins, and the app needs a new build after adding it.
