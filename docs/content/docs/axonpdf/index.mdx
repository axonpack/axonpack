`@axonpdf/react` turns React components into PDF files. You build the document from components
such as `Document`, `Page`, `View` and `Text`, lay it out with flexbox, and render it to a file, a
stream, a Blob or a viewer. Layout and PDF writing run in a Rust engine compiled to WebAssembly,
which is published on its own as `@axonpdf/core`.

```sh
npm install @axonpdf/react react
```

<LatestRelease slug="axonpdf" />

```tsx
import { Document, Page, Text, renderToFile } from '@axonpdf/react';

await renderToFile(
  <Document title="Hello">
    <Page size="A4" style={{ padding: 40 }}>
      <Text>Hello</Text>
    </Page>
  </Document>,
  'hello.pdf',
);
```

## What it does

| Feature                     | What you get                                                                                   | Page                                                  |
| --------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| Components                  | `Document`, `Page`, `View`, `Text`, `Link`, `Image`, `Canvas`, SVG and fillable form fields     | [Components](/docs/axonpdf/react/components)                |
| Styles                      | Flexbox, borders, transforms, media queries, floats and bidirectional text                     | [Styling](/docs/axonpdf/react/styling)                      |
| Fonts                       | TrueType, OpenType, WOFF and WOFF2, embedded as subsets, with hyphenation and emoji            | [Fonts](/docs/axonpdf/react/fonts)                          |
| Rendering                   | Files, buffers and streams in Node; Blobs, a viewer and a download link in the browser          | [Rendering](/docs/axonpdf/react/rendering)                  |
| Streaming                   | Each page is written to the file or stream as soon as it is laid out                            | [Rendering](/docs/axonpdf/react/rendering#streaming-from-a-server) |
| `Rows`                      | Rows from an array or an async iterable, rendered and written in batches                       | [Long documents](/docs/axonpdf/react/long-documents)        |
| `PageNumber`, `PageCount`   | The page number and count as text                                                              | [axonpdf extras](/docs/axonpdf/react/extras)                |
| Tables                      | `Table` with a header row that repeats on every page and borders that collapse                  | [axonpdf extras](/docs/axonpdf/react/extras#tables)         |
| Header and footer bands     | `header` and `footer` on `Page`, and the content area shrinks to fit them                       | [axonpdf extras](/docs/axonpdf/react/extras#header-and-footer-bands) |
| Web Worker                  | The whole render off the page's main thread                                                     | [Web Worker](/docs/axonpdf/react/web-worker)                |
| Profiler                    | `profile()` reports time per phase and per page, and memory                                     | [Profiling](/docs/axonpdf/react/profiling)                  |
| Security and archiving      | Passwords, permissions and PDF/A                                                               | [Security and archiving](/docs/axonpdf/react/security-and-archiving) |
| Engine                      | Layout and PDF writing in Rust, compiled to WebAssembly                                        | [Core engine](/docs/axonpdf/core)                     |

Coming from react-pdf? Its API is compatible, and [Migrate from react-pdf](/docs/axonpdf/migrate-from-react-pdf)
shows how to switch with one import.

## Performance

One A4 report with a logo, three paragraphs and a five-column table that runs across every page,
rendered in Node on an Apple M4 (24 GB RAM, Node 24.11.0) with React in production mode. Each cell
is the render time, the peak memory of the whole process, and the size of the PDF.

| Engine                         | 100 pages                | 1000 pages                | 5000 pages                 |
| ------------------------------ | ------------------------ | ------------------------- | -------------------------- |
| axonpdf, rows as an array      | 817 ms, 117 MB, 442 KB   | 7.8 s, 154 MB, 4.3 MB     | 39.2 s, 471 MB, 21.5 MB    |
| axonpdf, rows from a generator | 863 ms, 117 MB, 442 KB   | 7.8 s, 130 MB, 4.3 MB     | 39.2 s, 215 MB, 21.5 MB    |
| axonpdf, rows in `<Rows>`      | 527 ms, 129 MB, 447 KB   | 4.8 s, 147 MB, 4.3 MB     | 24.1 s, 259 MB, 21.7 MB    |
| react-pdf 4.9.0                | 36.1 s, 1289 MB, 643 KB  | stopped at 15 min         | not run                    |
| pdfkit 0.21.0                  | 145 ms, 97 MB, 357 KB    | 1.1 s, 175 MB, 3.5 MB     | 5.3 s, 347 MB, 17.3 MB     |

pdfkit draws the same pages by hand with page breaks worked out in advance, so read its row as a
lower bound.

In Chrome, the live benchmark app renders a shipping ledger. Each cell is the time to the finished
PDF, then the longest time the page froze. With axonpdf in a Web Worker the page stays responsive:

| Pages | axonpdf, Web Worker | react-pdf 4.9.0       |
| ----- | ------------------- | --------------------- |
| 100   | 0.90 s, 18 ms       | 33.7 s, 33.6 s        |
| 500   | 3.9 s, 17 ms        | no PDF after 10 min   |
| 2000  | 16.2 s, 19 ms       | no PDF after 10 min   |

The [benchmarks page](/docs/axonpdf/benchmarks#in-the-browser) has the full table, with axonpdf on
the main thread too, and the live app, which will be published later {/* LIVE-APP-URL */}.

[Benchmarks](/docs/axonpdf/benchmarks) has the method, the commit and the command that reruns
every row.

## Packages

| Package          | What it is                                                                       |
| ---------------- | -------------------------------------------------------------------------------- |
| `@axonpdf/react` | The components, styles, fonts and render functions. Most apps need only this one. |
| `@axonpdf/core`  | The engine as WebAssembly, for writing a binding for another framework. See [Core engine](/docs/axonpdf/core). |
