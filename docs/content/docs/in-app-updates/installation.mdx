You need this page once, when you add the package.

```sh
npx expo install @axonpack/in-app-updates expo-application expo-localization
```

That is all for an Expo app. It runs in Expo Go and needs no `pod install` of its own.

## Requirements

| Needs                 | When                                                                          |
| --------------------- | ----------------------------------------------------------------------------- |
| React 18 or later     | Always                                                                        |
| React Native 0.72 or later | Always                                                                   |
| Expo SDK 52 or later  | Only for the [Google Play in-app update](/docs/in-app-updates/play-in-app-updates), which also needs a development build |

The example app is built on Expo SDK 58. iOS 27 needs Expo SDK 58 or later; after moving an app to
it, regenerate the iOS project with `npx expo prebuild --clean -p ios`, since a stale `ios/` folder
crashes at launch.

## What each package does

| Package             | Needed? | What it is for                                                         |
| ------------------- | ------- | ---------------------------------------------------------------------- |
| `react`, `react-native` | Yes | The prompt and the checks                                              |
| `expo-application`  | Yes\*   | Reads the installed version, build number and bundle id                |
| `expo-localization` | No      | Finds the user's country, so the App Store lookup uses the right one   |
| `expo`              | No      | Only for the [Google Play in-app update](/docs/in-app-updates/play-in-app-updates) |
| `expo-updates`      | No      | Only if you use Expo over-the-air updates with `checkOtaUpdate()`      |

\* Or give your own values, as shown below.

The optional packages are never installed for you. Your app keeps its own single copy of each, so
there are no duplicate native modules.

## The version source

The package needs to know your installed version. It calls this the **version source**. By default
it reads it from `expo-application`. If your app does not use `expo-application`, set your own values
once, at the top of your entry file:

```ts
import { setVersionInfo } from '@axonpack/in-app-updates';

setVersionInfo({
  getCountry: () => 'US',
  getPackageName: () => 'com.example.app',
  getCurrentBuildNumber: () => 42,
  getCurrentVersion: () => '1.4.0',
});
```

If there is no version source at all, the first check fails with a `VersionInfoUnavailableError`
that tells you to install `expo-application` or call `setVersionInfo`.

## The country

The App Store keeps a separate page for your app in each country. The package asks for the one that
matches the user's country, taken from `expo-localization`. If your app is not on that page, it asks
the US page instead. You can change that with `fallbackCountry`.

## Give your AI agent the skill

If you work with a coding agent, install this package's skill into the project:

```sh
npx skills add axonpack/axonpack --skill axonpack axonpack-in-app-updates
```

Then you can ask it to "Set up @axonpack/in-app-updates in this app", and it follows the setup in the
skill. [Agent skills](/docs/agent-skills) has the command for each package manager.
