Most apps never need this page. Read it if your version looks different from `1.2.3`, for example a
date, or a beta or canary tag.

The comparison does not need strict semver (the `1.2.3` style).

| Format                         | Example                                              |
| ------------------------------ | ---------------------------------------------------- |
| One to many numbers            | `1`, `1.2`, `1.2.3.4`                                |
| A leading `v`, or a label      | `v1.2.3`, `canary-1.2.3`                             |
| Calendar versions              | `2024.10.1`                                          |
| Plain dates                    | `2024-10-12`                                         |
| Release tags                   | `1.2.3-beta.2`, `1.2.3-rc1`, `1.2.3beta`             |
| Tags with build info           | `1.2.3-canary.5+sha.abc` (the part after `+` is ignored) |

Missing parts count as zero, so `1.2` and `1.2.0` are the same. Numbers are compared as numbers, so
`1.10` is newer than `1.9`.

## Beta, canary and other tags

A tag sorts below its release: `1.2.3-beta` is older than `1.2.3`. Tags on the same release go in the
order they usually ship: `dev`, `nightly`, `canary`, `alpha`, `beta`, `preview`, `pre`, `rc`. Other
words sort alphabetically. Numbers inside a tag are compared as numbers, so `rc2` comes before `rc10`.

## A format the package cannot read

A version with no number at all (`canary`), or odd text (`2.0 (build 5)`), is rejected with an
`InvalidVersionError`. Give your own comparison instead:

```tsx
import { UpdatePrompt } from '@axonpack/in-app-updates';
import { Text, View } from 'react-native';

const digits = (v: string) => Number(v.replace(/\D/g, ''));

export default function App() {
  return (
    <View style={{ flex: 1 }}>
      <Text>My app</Text>
      {/* Like Array.sort: negative, zero or positive */}
      <UpdatePrompt compare={(a, b) => digits(a) - digits(b)} />
    </View>
  );
}
```

`compare` is used for every decision: is there an update, the minimum version, and skip. `depth` is
ignored while it is set. `updateType` falls back to `patch` for any newer version it cannot size.

## Build numbers

When the store and the app have the same version, a provider can still report a higher build number.
That counts as an update of type `build`.

The App Store and the Play Store page report no build number, so this only works with your own JSON
endpoint (`buildNumber` or `latestBuildNumber`), or with the `latestBuildNumber` option. Give
`needUpdate` both numbers:

```ts
import { needUpdate } from '@axonpack/in-app-updates';

const result = await needUpdate({
  latestVersion: '1.4.0',
  currentVersion: '1.4.0',
  currentBuildNumber: 41,
  latestBuildNumber: 42,
  ignoreErrors: false,
});
// result.updateType === 'build'
```

## Helpers

`compareVersions`, `isGreater`, `satisfiesMinimum`, `diffVersions`, `parseVersion` and
`truncateVersion` are exported, so your own code compares versions the same way.
